# 中文版本测试与验收规范

## 基准和范围

遵循李笑来原仓库 `xiaolai/checkmate` 的 `docs/development.md`、`docs/releases.md`、`scripts/gates.json` 和 `docs/training-observation.md`。固定英文基线为 `b266339003c6897d3c9e5d7d8ca758c6065c5362`（0.9.3 / build 32）。本规范按用户于 2026-11-19 的要求制定，替代另建全面对抗性测试项目的建议。

目标是中文版本与英文原版功能等价。规则、棋局机械数据、课程顺序、判分、合法走法、提示等级及存档/进度不得因翻译改变。允许中文呈现、音频、必要的布局适配、已批准的兼容性修复，以及 DeepSeek 提供方和中文语音链路差异。DeepSeek 是默认且唯一自动选择的回答模型，不得回退到 Codex。

**主要被测对象始终是当前开发的中文程序。** 复用的是原仓库的测试规范、用例、执行机制和业务断言，再作必要适配。英文运行只提供必要的行为对照，不能作为中文功能、文案或布局已经验收的证据。

## 复用和适配方式

| 原测试类型 | 中文版处理方式 |
| --- | --- |
| 规则、引擎、机械数据、协议等与语言无关的测试 | 原样复用，检查当前中文项目的相同模块 |
| 点击、导航、课程、练习、复盘、设置、保存恢复等界面测试 | 保留原操作流程与业务断言，实际在中文界面运行；优先用稳定控件 ID 定位，必要时使用对应中文文案 |
| 文案、反馈、无障碍和布局断言 | 按等义中文与中文字体布局适配，保留变量、棋格、答案键、几何及操作结果断言 |
| 旧模型提供方专属测试 | 保留可复用的授权、取消、局面隔离等行为要求，适配 DeepSeek；仅旧通道兼容性子场景使用静默替身，单独记录 |
| 英文对照运行 | 需要排查差异时作为补充；与中文主验收分开报告 |

每个原门禁先标明“可直接复用 / 需中文适配 / 需 DeepSeek 适配 / 环境待补”，再执行实际可用的测试。不能因为脚本写死英文就把主要测试对象改成英文，也不能删除业务断言使测试通过。

## 三层验证

1. **中文版业务回归**：继承原 24 个门禁的覆盖目标及业务断言。涉及用户界面的主流程在 `zh-Hans` 下执行，覆盖课程、练习、导航、复盘、设置、点击及存档恢复，而不只补跑 UI/全屏/布局三项。语言无关的单元及协议测试原样复用。旧通道的兼容性测试独立记录，不能替代默认 DeepSeek 的业务验收。
2. **中文等价与显示**：`chinese` 扩展门禁检查英文规则/引擎/课程机械资源的基线一致性、中文目录及占位符、棋格记号、课程片段及题库覆盖；中文主流程同时验证可见文案、操作反馈、无障碍和布局。这些检查覆盖结构和可见交互，不能声称已经逐句人工审校全部中文。
3. **DeepSeek 改写**：默认选择、授权、只读工具、当前局面绑定、取消、超时、用量归属由专门测试验证；真实 DeepSeek 联调与应用内中文识别/播放单独记录，沿用原版“真实服务及人工验收与静默自动化分开”的规则。自动化不得使用真实 Codex、麦克风或扬声器。

`CheckmateDeepSeekAcceptance` 现支持 practice、review、training 三种作用域。本次另执行 review 和 training 各一次真实小样，核对实际作用域、FEN、回答来源、工具参数和成功结果，并保存模型与用量；不是只检查模型是否提出工具调用。小游戏朗读由零模型调用的本地驱动合同验证。真实小样不证明自由回答逐句正确，也不替代麦克风或扬声器实测。网络等未完成项在修复并取得对应中文证据前，阻止声称“原功能已完整等价”，但不抹去已验证场景的记录。

中文文案判断保留合理例外：棋格/SAN/UCI、模型品牌、用户输入、导入棋谱原文、玩家名及设备名可原样显示；不能把这些当成漏译，也不能借此放行应用自有界面和反馈文案中的漏译。

- 原 runner 的单次 targeted run 仍在首个失败处停止。分批结果可汇总成开发验收表，但不得伪造 `acceptance.json`；只有同一未变化源码的原完整运行才能生成正式全套证据。
- 原真实语音脚本依赖旧提供方，本项目不实际调用它；DeepSeek 真实联调使用 `CheckmateDeepSeekAcceptance`。用户此前确认的应用内中文识别与播放作为人工记录，必须标注其对应版本；涉及语音实现变化时重新验证。
